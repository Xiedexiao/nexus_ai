## Context

你现在的渠道 #1 是类型 60（New API），一条渠道同时服务 OpenAI 与 Claude 两种协议，靠上游同一 host 的不同路径区分。但很多上游网关把两种协议放在**不同 host 或不同路径前缀**上（例如 OpenAI 走 `https://a.example/v1`，Claude 走 `https://b.example/anthropic`）。目前一个渠道只有一个 `base_url`，只能选其中一种，另一种就得再建渠道 + 再建分组。

本次新增：**渠道级、按上游协议分别配置 Base URL**。三个槽位 `openai` / `claude` / `gemini`，留空则沿用渠道 Base URL。按你选的语义，槽位由**上游实际协议**决定（请求转换完成后再解析），所以"OpenAI 客户端 → Anthropic 渠道"这种组合也会正确落到 claude 槽位。

## 关键设计

**唯一解析点**：`backend/relay/channel/api_request.go` 里三个出站漏斗 `DoApiRequest` / `DoFormRequest` / `DoWssRequest`，它们都在调用 `a.GetRequestURL(info)` 之前。此处 `info.RequestConversionChain` 已由各 handler 在转换后填好，最后一项就是上游真实协议；覆盖写 `info.ChannelBaseUrl` 后，全部 37 个读该字段的 adaptor 自动生效，无需逐个改。

```
slot := GetFinalRequestRelayFormat()   // claude → "claude"; gemini → "gemini"; 其余 → "openai"
if override := ChannelSetting.ProtocolBaseURLs[slot]; override != "" {
    info.ChannelBaseUrl = strings.TrimRight(override, "/")
}
```

**不改 gin context 里的 `ContextKeyChannelBaseUrl`**：`responses_websocket.go:568` 用它与 `channel.GetBaseURL()` 比较来判断"是否需要重连"，改写会导致每次 WS 重连都被拒绝。因此错误脱敏改为在 `common/gin.go` 的 `UpstreamAddresses` 里把三个 override 直接加进候选列表（和现有 `setting.Proxy` 同一行位置），避免私有上游地址泄漏给终端用户。

## 改动清单

### Backend

1. **`backend/relaykit/dto/channel_settings.go`**
   - `ChannelSettings` 增加 `ProtocolBaseURLs map[string]string \`json:"protocol_base_urls,omitempty"\``
   - 常量 `ProtocolSlotOpenAI = "openai"` / `ProtocolSlotClaude = "claude"` / `ProtocolSlotGemini = "gemini"`
   - `func (s ChannelSettings) ProtocolBaseURLFor(format types.RelayFormat) string`：claude→claude 槽、gemini→gemini 槽、其它（含 responses/embedding/realtime）→openai 槽；返回 trim 掉尾部 `/` 的值
   - `func (s *ChannelSettings) ValidateProtocolBaseURLs() error`：key 必须是三个槽位之一；值必须为空或绝对 `http`/`https` URL 且有 host。错误信息格式对齐现有 `ValidateHTTPTransport` 的 `invalid xxx: %s`

## 不做的事
- 不改任何数据库结构：新字段落在已有的 `channels.setting` TEXT 列里，走既有的 `GetSetting` JSON 解析，无迁移、无需三库验证矩阵（会在总结中明确说明这一判断）
- 不动 `ChannelSpecialBase` 那套硬编码 coding-plan 表，两者互不干扰（override 优先于 plan：adaptor 里的 plan 查找用的是已被改写后的 `info.ChannelBaseUrl`，admin 显式配置的值会赢）
- 不覆盖 ollama / baidu / coze / dify / replicate 等自行拼 URL 的 adaptor —— 它们的请求不经过三个漏斗。会在说明里注明限制
